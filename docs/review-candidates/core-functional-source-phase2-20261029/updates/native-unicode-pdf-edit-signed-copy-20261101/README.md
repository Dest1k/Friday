Unicode PDF forms, literal editing and unsigned copies

This reviewed source-only block follows Native Source128.

PDF text forms support bounded Latin/Cyrillic values using a pinned embedded DejaVu Sans font. Visible appearance streams, field values and Unicode mappings are checked together. Existing annotations are retained across either order of filling and annotation. Complex shaping, unsupported glyphs, bidi/combining text and oversized values refuse.

Literal PDF editing replaces one unique complete Courier ASCII text operand in a new document. Equal length and identical space positions retain advances. Other native operators, resources and page geometry are verified; this is a narrow profile, not a general layout editor. The redaction operation keeps its separate conservative rules.

Signed-PDF handling exposes structural signature inventory with an explicit NOT_CRYPTOGRAPHICALLY_VERIFIED status. A separately requested unsigned derivative drops digital-signature widgets and appearances, form state and document metadata while preserving supported page content. It never signs a file or asserts certificate, cryptographic, trust or legal validity. Original signed bytes remain unchanged. Signature-looking artwork already embedded in page content can remain and proves nothing.

Source hashes, scoped paths, create-only publication, cancellation and uncertain-effect handling are retained. Original failures and checker corrections remain in private evidence. Installed Source117 is unchanged; installation, Office, Telegram and live user acceptance remain pending.
