Protected files, Word template fill and PDF text removal

This source-only block follows Native Source127. It composes four ordinary file capabilities with independent component and integration review.

Encrypted ZIP creation uses AES256 AE2; reading and extraction support a bounded authenticated AE1/AE2 stored/deflate profile. All local and central encryption markers are checked. Member names remain visible, and encrypted editing or conversion is unsupported.

Supported encrypted PDFs can be read with a supplied password when extraction is permitted. The plaintext exists only inside the bounded private execution path and is not published. PDF form reading and writes do not accept this password parameter.

Word templates accept explicit literal field values and an exact source hash. Filling preserves unrelated package content and writes a new DOCX, including from a supported DOTX. Missing or extra values, unsupported placeholder locations, active content and ambiguous formatting refuse.

PDF text removal writes a fresh PDF containing no old revisions. The supported profile requires unique complete ASCII Tj operands. It conservatively refuses when surviving glyphs could reconstruct a removed target, even in a different order. This narrower operation does not claim general layout-aware redaction.

Original failures and corrected checker observations remain recorded in private evidence. Installed Source117 is unchanged; installation, Office rendering, Telegram and live user acceptance remain pending.
