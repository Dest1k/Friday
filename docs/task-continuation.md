# Retained task continuation

The ordinary `friday_work` tool accepts an optional `from_result` object:

```json
{
  "worker": "a0",
  "brief": "Check the returned source files and fix the observed configuration problem.",
  "goal_check": "The original unchanged completion criterion.",
  "from_result": {
    "reference": "native-<owned predecessor reference>",
    "paths": ["src/main.py", "README.md"]
  }
}
```

Use exact `source_paths` from a result already frozen by `friday_result inspect`.
Tool arguments select retained data. Native Hermes middleware, the current
session and its admitted user scope supply authority. The reference cannot
nominate a host repository, credentials, a replacement context or new clocks.
The original user, bot, chat, topic, profile, transport and session remain bound.
The original `goal_check` must be unchanged. A `/new` session cannot acquire the
previous session's continuation by matching its chat.

The association document retains a predecessor/successor chain and the original
acceptance clock. It stays the single small ownership ledger. Each stage inherits
the root's creation time, budget and deadline, plus elapsed high-water. The
current boot's monotonic clock also caps remaining time. Legacy records remain
readable and stoppable; a missing original clock is an explicit continuation
refusal, without inventing or upgrading a grant. Cancelled, paused, expired,
unknown or unquiet stages cannot continue. A duplicate native tool call reads
its original association. A new call cannot branch from a predecessor whose
custody was already transferred. A failed copy, preparation or uncertain launch
reserves the stage and never authorizes an automatic retry.

Administrative pause/cancel also persists after a stage has completed. It
retains the finished result and prevents a subsequent continuation; status alone
does not change intent. Both worker admission receipts bind the exact
`continuation.py` helper, so older receipts cannot admit changed seeding code.
Directory creation and verification stay relative to open directory descriptors;
A0 walks from its bound state directory through `workdir`, job and seed. A
replaced directory path cannot redirect writes into another tree.

Before admission, the host freshly checks the departing native boundary. For
DSH this is the supervised unit and its cgroup; for A0 it uses the existing exact
dedicated environment stop/cessation path. A historical completion flag alone
is insufficient. Admission closes predecessor custody atomically with reserving
one successor. The successor gets a new private workspace, never simultaneous
write access to the preceding tree. No scheduling, worker pool, daemon or goal
manager is added. The existing supervisor and native worker remain execution
owners.

Selected artifacts are copied from the frozen, bounded, hashed manifest into
private staging. Paths must be relative, bounded, distinct and free of hidden
components, credentials, hooks, links or path conflicts. DSH receives actual
files under its native `/workspace` mount. A0 receives them through its existing
upload interface; after its harmless context initialization, the adapter seeds
only the exact owned `/a0/usr/workdir/<job-prefix>/seed` mount and checks the
native-visible bytes. Both adapters check the seed manifest before effectful
submission. Seed files are untrusted project data. No git metadata, hooks,
owner checkout or unrelated credentials are copied.

This mode is **cold retained artifact continuation**. DSH starts a new bounded
native session and A0 initializes a new bounded native context. Their actual
identities remain in their existing receipts. Neither native history nor warm
context is fabricated. An original reference passed to native stop/pause/status
resolves the current writer; stop intent is retained across the chain. A checked
current writer remains stoppable through the existing emergency path if durable
metadata becomes unreadable. No successful acknowledgement is returned until
stop and persistence are proved. Result status/assessment/delivery resolve the
current stage; historical list/inspect still read their exact selected record.
Delivery keeps the root's original destination, including reply/topic/session.
Execution completion and file integrity never certify the user's goal.

Source checks exercise ordinary PluginManager, middleware, PluginState,
WorkerHost, both adapter preparations, native file interfaces, filesystem
seeding and control dispatch with explicit offline systemd/Docker/API fixtures.
They include Harness → A0 → Harness, original single-worker behavior and
meaningful refusal cases. They are not live acceptance.

Arbitrary host repository admission, complete repository/dirty manifests,
archive extraction, warm session/context reuse, independent execution of goal
checks and all seven live journeys remain unresolved. Worker-map/config joining
belongs to Astra's separate package; this source candidate still uses the
existing single configured route, switched in the offline handoff control.
A0 G4 remains closed, G5 NOT_RUN, product kernel 120 NOT_GRANTED_NOT_RUN. This
source change grants none of these executions and does not make the product
ready. Astra also preserves its separately owned keyless DNS correction at join.
