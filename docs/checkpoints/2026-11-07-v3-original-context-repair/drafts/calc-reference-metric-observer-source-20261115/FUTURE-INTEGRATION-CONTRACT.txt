Purpose and exact capture
The supplied hook observes ten separate, sequential, one-digit getStringWidth
calls from one Root-qualified private Office instance. It is not an Office build,
bridge, general tracing service, permanent dependency, or historical producer proof.
The numeric scalar remains RAW_CURRENT_REFERENCE_DEVICE_LOGICAL_SCALAR. It does
not establish physical pixels/twips, actual M, physical fidelity or case acceptance.

Accepted platform assumptions: ordinary publisher source/build attribution for
Ubuntu amd64 LibreOffice26.2.5.2, LP64 tools::Long signed64/sal_Int32 signed32,
x86-64 System V C++ member calling convention. Exact scalar integer return is RAX
(long64) and low EAX (int32). Register bits are decoded signed, without debugger
return-type inference. This/first reference argument arrive in RDI/RSI; start,
length, text cache and glyph arguments arrive RDX/RCX/R8/R9. No debugtypes required.
The accepted OUString layout is a sole pData pointer at0; rtl_uString has int32
refCount at0, int32 length at4, UTF16 buffer at8. The exact source headers/pins
are retained. These layout assumptions are explicit, not a custom runtime build.

Pinned binary source/caller feasibility: dynamic outer symbol0x3df84b0 directly
calls native0x4566cd0 at outer+0x84, return PC outer+0x89=0x3df8539. Bytes at
that return PC are488d75b04c89e789c3. Hook reads FULL RAX there, before the first
narrowing mov EAX,EBX at outer+0x90. The nonvirtual thunk at0x3df85a0 is never
instrumented, so it is not double counted. A thread-specific FinishBreakpoint
then reads EAX at the outer function's caller before further caller execution.
Normal unwindable frames/usable CFI, exact registers and exact runtime symbols
are required. Missing symbols, CFI/register availability, ptrace denial, signals,
fork/vfork/exec, unexpected stop, wrong argument/content/thread/device/frame,
unknown phase or incomplete/extra calls produce REFUSED, never evidence release.
CFI/runtime success on real Office remains untested; installed .eh_frame presence
is only feasibility. No promise that an Office run will pass is made.

Plain phase protocol
Root atomically writes EXACT four keys: nonce,phase,index,digit. Initial phase is
{"nonce":"<fresh32hex>","phase":"IDLE","index":null,"digit":null}.
The hook starts its own executable at starti, records PID/start_ticks/direct GDB
parent, resolves pinned relocated symbols, verifies return-site bytes, then emits
trace status READY_UNRELEASED. Root waits for readiness with its bounded outer
runner before issuing the metric client calls. No hook polling/watcher exists;
phase is read only when an actual breakpoint or final validation occurs.
Before each single synchronous call Root atomically writes METRIC,index0..9,
digit "0".."9"; Root must hold that exact phase until the UNO call returns. Hook
checks the actual OUString memory at both entries. Startup calls are ignored only
before any captured metric; a later outer call outside METRIC is refused. Native
entry/return breakpoints are enabled only between the exact outer entry and its
finish; unrelated/background calls during that interval fail closed. One thread,
one VCLXFont and one OutputDevice are bound. Other phase changes during a call,
recursive calls, duplicates, missing returns or a wrong caller PC cannot release.
The synchronous GDB resume loop alone creates/enables/disables breakpoints; its
Breakpoint.stop callbacks only inspect/record/set a pending action and stop.

After ten query responses, Root completes exact full-Font restoration, unchanged
modified flag and private read-only document close without save. It writes CLOSED
with null index/digit only after the final call has returned. It then shuts down
that own Office instance normally. No fork/foreign process cleanup is assumed.
Only exact exit0, CLOSED, ten complete paired calls, raw0<W<65536, raw64=outer32,
no error and the original process absent yield COMPLETE_UNATTESTED. Error path
kills only the confirmed direct own inferior; unexpected fork/multiple-inferior
cleanup stays REFUSED/UNKNOWN and Root must clean its own cgroup/namespace/tree.
The outer deadline must clean the entire OWN operation if GDB is externally killed.
