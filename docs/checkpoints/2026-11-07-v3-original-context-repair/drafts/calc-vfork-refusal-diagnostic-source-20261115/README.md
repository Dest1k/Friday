# Calc: отказная диагностика процесса — SOURCE

Добавлены только ограниченные символические кадры (≤24, без аргументов, локальных
данных и регистров), PID/PTID и ≤8 numeric children перед прежним отказом
`unexpected_fork_vfork_exec`. Исходные native guards, основной цикл, вызов kill и
cleanup сохранены. Код ничего не разрешает и не возобновляет после fork/exec.

Независимая проверка Root: AST-равенство всей прежней программы за исключением
диагностической вставки; реальный GDB на маленьком собственном vfork-примере
показал нужный символический стек, сохранил REFUSED, закрыл процессы. 11 инертных
тестов исполнителя проверили границы/ошибки. Тесты используют точные локальные
пути исходной рабочей среды; это архив проверенного кода, не автономная установка.
Первый запуск тестовой обвязки отказал из-за слишком малого RLIMIT_AS для GDB;
отказ сохранён, исправлен только этот неподходящий лимит. RLIMIT_AS не RSS.
Продуктовые бюджеты не изменены.

В отдельной конечной private readonly диагностике Office получены 24 символических
кадра: ScDocShell::Load → ScStyleSheetPool::CreateStandardStyles →
ScStyleSheet::GetItemSet → SvxPaperInfo::GetDefaultPaperSize →
PaperInfo::getSystemDefaultPaper → popen → posix_spawn → clone3/vfork. Прежний
строгий guard остановил исполнение; LOAD вернулся DisposedException. Внутренняя
частичная инициализация не исключена; MODEL_LOADED checkpoint отсутствует,
метрических записей нет. Исторический R2 отказ не переписан.

Это объяснение конкретной зависимости LOAD, не её поддержка. Нужен отдельный
проверенный контракт обычного paper-helper, без изменения reference-конфигурации,
общего разрешения subprocess и повторения пользовательской отправки/конвертации.
Installed224 неизменна; M, historical applicability, physical fidelity,
полная F04/B00/V3 и формальная приёмка остаются открытыми.

Private документы, профили, cache payload, grants/plans и rawlogs не публикуются.
