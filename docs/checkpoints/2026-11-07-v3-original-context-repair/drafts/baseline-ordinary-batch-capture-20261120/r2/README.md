# Восстановление записи пакета обычного тестера Telegram

R1 сохраняет обновления перед их обработкой. При остановке между записями двух обновлений оставшаяся часть пакета и исходное время её получения ещё могли находиться только в памяти.

R2 сначала сохраняет в защищённом `Store` один файл на непустой пакет. Первая строка содержит исходное время получения, смещение, номер записи, ссылку на предыдущую запись и SHA-256 контекста. После перевода строки лежит точное тело ответа Bot API. Запись `poll_batch` связывает размер и SHA-256 этого файла с существующими головами журнала и курсора до записи отдельных обновлений. При разрешённом повторе чтения статус возврата записывается после этой фиксации.

При согласованных головах наблюдатель дочитывает из файла только ещё не зафиксированные обновления с исходным временем. Сбой между записями отдельных обновлений проверен после истечения окна. Наблюдатель восстановил оба результата без повторного обычного чтения или отправки исходного файла. Штатное однократное финальное чтение подтвердило окно. При расхождении голов или непарной записи восстановление прекращается до любых запросов. Целый файл пакета сохраняет байты и время для отдельной оценки. При остановке до первой устойчивой записи из журнала нельзя установить, был ли получен пакет и какие байты или время ему принадлежали. Тест фиксирует эту границу без присвоения статуса завершённого окна.

## Проверка без сети

Команда для запуска из корня Friday_rework.

```bash
(
  set -e
  checkpoint=docs/checkpoints/2026-11-07-v3-original-context-repair
  draft="$checkpoint/drafts/baseline-ordinary-batch-capture-20261120"
  candidate_dir=$(mktemp -d)
  trap 'rm -r -- "$candidate_dir"' EXIT
  source="$checkpoint/evidence/tester/bot_tester.installed.py"
  printf '%s  %s\n' cc36c0933bd01cfa5c33a3fb1123fefd0345a2185fbcf7f70f5a3bc2f7c0905b "$source" | sha256sum -c -
  cp "$source" "$candidate_dir/bot_tester.py"
  patch --batch --forward --fuzz=0 -d "$candidate_dir" -p1 < "$draft/ordinary-batch-capture.patch"
  cp "$candidate_dir/bot_tester.py" "$candidate_dir/bot_tester_r1.py"
  printf '%s  %s\n' 002fdbcada5e3cb4c516e01807177a2cbb573f439f24a2491e370d611c48b4af "$candidate_dir/bot_tester_r1.py" | sha256sum -c -
  patch --batch --forward --fuzz=0 -d "$candidate_dir" -p1 < "$draft/r2/ordinary-poll-witness.patch"
  printf '%s  %s\n' 2a328fb6763e638bc297502945b24aa595a1a76a54da21e06898912e098ceed2 "$candidate_dir/bot_tester.py" | sha256sum -c -
  python3 -I -B "$draft/r2/check_witness.py" "$candidate_dir/bot_tester.py" "$candidate_dir/bot_tester_r1.py" -v
)
```

Прошли 19 проверок, включая семь проверок R1. Точки остановки охватывают запись до и после сохранения тела, до и после фиксации обеих голов, чистую остановку после первого обновления и неполную запись второго. Проверены подмена файла, разрешённый повтор чтения, восстановление после ограничения частоты, два последовательных пакета и побайтовая сохранность квитанций R1 при чтении R2.

В тестах использованы настоящий локальный журнал, временный каталог и синтетические транспорт и часы. Установка, реальный Telegram, защищённая история и дополнительная длительность проверки сохранённых тел не проверялись. Кандидат хранит один файл размером до 1 МиБ плюс ограниченный заголовок на непустой обычный пакет. Ранее записанные квитанции не требуют миграции.
