# Сохранение пакета ответов обычного тестера Telegram

Штатный наблюдатель по очереди сохраняет и обрабатывает обновления из одного ответа `getUpdates`. Из-за задержки на скачивании следующий ответ из того же пакета может получить время после отсечки. Если обработка первого обновления завершается отказом, следующие обновления из уже полученного пакета остаются только в памяти процесса.

Кандидат фиксирует одно время при получении пакета и сохраняет все его обновления в существующем журнале до проверки ответов и скачивания файлов. Объём пакета ограничен запрошенным лимитом. Допустимость ответа по исходному окну, лимиты документов, статусы STOPPED/UNKNOWN и отдельное подтверждение завершения окна сохраняются.

| Файл | SHA-256 |
| --- | --- |
| `evidence/tester/bot_tester.installed.py` и установленный тестер | `cc36c0933bd01cfa5c33a3fb1123fefd0345a2185fbcf7f70f5a3bc2f7c0905b` |
| Кандидат `bot_tester.py`, полученный применением патча | `002fdbcada5e3cb4c516e01807177a2cbb573f439f24a2491e370d611c48b4af` |

## Проверка без сети

Команда для запуска из корня Friday_rework.

```bash
(
  set -e
  checkpoint=docs/checkpoints/2026-11-07-v3-original-context-repair
  draft="$checkpoint/drafts/baseline-ordinary-batch-capture-20261120"
  candidate_dir=$(mktemp -d)
  trap 'rm -r -- "$candidate_dir"' EXIT
  source="$checkpoint/evidence/tester/bot_tester.installed.py"
  printf '%s  %s\n' cc36c0933bd01cfa5c33a3fb1123fefd0345a2185fbcf7f70f5a3bc2f7c0905b "$source" | sha256sum -c -
  cp "$source" "$candidate_dir/bot_tester.py"
  patch --batch --forward --fuzz=0 -d "$candidate_dir" -p1 < "$draft/ordinary-batch-capture.patch"
  printf '%s  %s\n' 002fdbcada5e3cb4c516e01807177a2cbb573f439f24a2491e370d611c48b4af "$candidate_dir/bot_tester.py" | sha256sum -c -
  python3 -I -B "$draft/check_capture.py" "$candidate_dir/bot_tester.py" -v
)
```

Семь проверок кандидата прошли. На исходнике воспроизведены пять расхождений: поздняя метка своевременного текста после скачивания, утрата соседнего обновления при локальном отказе, неполное восстановление после остановки перед обработкой, поздняя метка при записи результата разрешённого повтора чтения и приём превышенного пакета до проверки лимита. Оба снимка сохранили эффект UNKNOWN после потери ACK отправки и после потери ответа финального чтения. В первом случае повторной отправки не было. Во втором случае сохранён ранее полученный текст и повторного финального чтения не было.

Проверки вызывают реальные методы `Runner.new`, `send`, `observe`, `load` и `verify_reply_custody` с временным `Store`, синтетическими файлами, транспортом и часами. Проверены текст, хеш скачанного файла, исходное окно и граница между завершённым сбором и незакрытым эффектом. Допуск реального продолжения, время исполнения на защищённом состоянии и живой Telegram этим запуском не проверялись. Установленный тестер и архивный снимок сохранены.
