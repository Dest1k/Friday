# Selected same-format rich byte assessment

`rich_join.assess_received_saved` is a pure, finite function. It reads no paths,
constructs no workbook, runs no evaluator and performs no external effects.
Every workbook, library and private fact is passed as explicit bytes. A match
establishes selected facts about those supplied bytes only. All authority,
runtime, custody, independence, installed-version, delivery, nonreplay and
acceptance claims remain false on every result.

The fixed profile has three sheets, four multiplication formulas, one separate
cross-sheet sum, four text identifiers, one selected bar-family chart and series,
one custom named range, one effective equality/set filter, and one absolute
integer-between validation. Required features come from the explicit original
XLSX authority, not the saved or received caches. The received baseline supplies
current preservation facts. No sheet names, literal business values, filenames,
paths or original cache totals are built into the module.

Call with keyword arguments:

```python
report = assess_received_saved(
    source_bytes=source_ods,
    received_bytes=received_ods,
    saved_bytes=saved_ods,
    authority_bytes=original_feature_authority_xlsx,
    independent_fact_bytes=private_root_precommit_json_bytes,
    request=request,
    delta=controlled_delta,
    projection=private_projection_binding,
    oracle=private_cache_oracle,
    pins=pins,
    libraries=libraries,
)
```

`libraries` has exactly `structures`, `strict`, `received`, `preservation`, and
`recalc`, each containing the exact source bytes whose pinned digest is in
`LIBRARY_PINS`. The original structure library is loaded by selecting its pure
`xlsx`, `ods`, `rich` and parser helper definitions. Its archive provider is
replaced by an exact in-memory ZIP provider with a fixed logical token.
Only `strict_rich` is selected from the old assessment flow, plus the separately
qualified bounded raw-cell helpers. Old context/main/oracle/driver code is never
executed. The two public byte checkers are explicitly supplied pinned pure
source modules; the helper import is satisfied by the supplied helper bytes.

`request` has exactly `sheet`, `cell`, `expected`, `value`, all strings. This
profile requires the original literal change at `C2` to be a numeric +1.
`delta` has exactly `kind`, `sheet_index`, `cell`, `before`, `after`, `addend`.
Its kind is `additional_independent_numeric_plus_one`, its one-based sheet index
is integer 1, its cell is `C2`, its addend is string `1`, and its before value
must equal the ordinary request value. Its after value must add another 1.

`oracle` follows the exact existing `friday.received-disposable-recalc.oracle.v1`
contract: `schema`, `received_sha256`, `request_sha256`, `delta`, and
`formula_caches_after`. Each of the five entries has `sheet_index`, `cell`,
`formula_sha256` over the exact raw received formula UTF-8 bytes, and string
`value`. Formula locations must cover every populated formula on all sheets.
All expected numbers must also match fresh Decimal arithmetic over the original
authority literals, the exact requested edit and the additional controlled edit.
No observed formula or chart cached value contributes to expected truth.

`independent_fact_bytes` is the separately supplied private precommit artifact,
schema `friday.Root.F03.independent-numeric-oracle-precommit.v1`. The adapter
crosschecks its source/request/delta bindings, original/ordinary/future five
numerical expectations, text IDs, source raw multiplication formulas and changed
formula locations. These checks establish agreement, not the artifact's
independence, authentication, custody or authority. Never give this artifact,
projection or oracle to the product, model, ordinary producer or Office input.

`projection` is an exact private binding manifest described by
`projection.schema.json`. It pins the explicit feature authority, source,
received bytes, ordinary request, controlled delta, independent private facts
and cache oracle. The actual XLSX-shaped expected semantic projection is built
only in memory from the supplied original feature authority and justified
literal inputs, with current received hidden rows and the controlled new literal.
It is not a constructed received/model-reply workbook. The result records a
digest of the derived semantic projection commitment.

`pins` has exactly nine lowercase SHA-256 strings: `source_sha256`,
`received_sha256`, `saved_sha256`, `authority_sha256`, `request_sha256`,
`delta_sha256`, `projection_sha256`, `oracle_sha256`, `independent_fact_sha256`.
JSON digests use UTF-8, `ensure_ascii=False`, sorted keys, no whitespace, and
`allow_nan=False`. The ordinary request must additionally match the retained
checker's ASCII canonical digest. The selected ordinary request is ASCII;
non-ASCII requests whose two canonical encodings differ are conservatively
refused. Hashes and labels never confer provenance.

Before invoking legacy readers the adapter validates finite ZIP members and
paths, XML and relationship XML declarations/processing instructions, XML
depth/element counts, repeats and expansion. It rejects nested row and column
groups unsupported by the selected parser. Whole-package checks permit the
chart frame outside the numeric columns and bounded repeated trailing empty
cells. The ordinary source-to-received edit must match the exact existing
checker, including noncontent payloads and all nontarget content bytes.
Before the retained reference normalizer runs, both endpoints of each selected
range are independently resolved. A second endpoint on another sheet is refused;
it cannot be erased by the legacy normalizer. The raw cross-sheet summary range
and the original authority's selected range references receive the same guard.

For received-to-saved it checks all populated raw cells, formulas, primitive
types, text IDs and cache coherence; all named ranges/scopes/ranges; every filter
declaration, Boolean tree, condition, set value, target and declaration count;
the validation definition, resolved references, all applied locations, absolute
integer bounds, allow-empty and stop/error behavior; all merges; current hidden
rows and columns plus resolved sheet display on all three sheets. Named
expressions and other unsupported profile forms are refused rather than ignored.

The selected chart's category/value/label refs, all source title texts/counts,
root/series bar class, one-chart/plot/series/category counts, freshly expected
visible cache and actual plot-style explicit include-hidden=false are checked.
Selected effective type/visibility properties (including orientation and
stacking) are preserved against the received baseline independently of generated
style identifiers. An omitted orientation/default declaration is conservatively
distinct from an inserted explicit value. This does not invent an unproven
cross-format default equivalence. Baseline formula/chart caches may remain stale;
their freshness is neither required nor reported as passed.
Every chart-cache table and row is accounted for within the selected one-header,
one-body, two-cell shape. Category strings and numeric caches have explicit
primitive types, coherent string-value/display text and numeric display values;
the cached series header also agrees with its original label cell.

The selected validation uses an absolute integer predicate. The adapter still
conservatively preserves its normalized base-cell declaration; a harmless base
change can therefore be refused even though it does not change this predicate.
The reused rich parser also resolves the existing source print/page style chain
to produce its historical observations. An unsupported or malformed chain is
refused; a successful parse promotes none of those historical dimensions or
physical-layout observations into newly proved fidelity.

Results contain fixed codes, hashes, bounded facts and explicit limitations.
No private literal values, formulas, IDs, exception messages or supplied reference
text are returned. A success state is
`SELECTED_RICH_BYTES_MATCH_EXPLICIT_PROJECTION`; other inputs yield `REFUSED` and
a fixed code. Every success still requires Root's separate genuine received,
runtime save/close/reopen, custody, once, immutable-input, capture, cleanup and
independent-provenance joins. It cannot establish App or F-03 acceptance.
`strict_rich_checked_report_sha256` hashes the exact in-memory rich report passed
to the unmodified `strict_rich` function. The report itself is not returned or
serialized; its digest is an assessment receipt, not an execution receipt.

Four known cross-format losses, four unassessed features and nineteen historical
dimension observations remain in their prior dispositions. Physical widths,
pagination, chart size and historical hidden/geometry provenance are unproved.
This module does not claim general ODS/Office fidelity or any runtime execution.
